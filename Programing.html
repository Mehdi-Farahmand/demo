۱

کلاس و شیء چیست؟

قالب کوکی را تصور کنید. قالب = کلاس (class) است؛ یک نقشه که می‌گوید کوکی چه شکلی دارد. هر کوکی = یک شیء (object) است که از روی آن قالب ساخته می‌شود. از یک قالب، هر تعداد کوکی می‌توان ساخت و هر کدام ویژگی‌های خودش را دارد.

class Dog:
    def __init__(self, name):    # سازنده: هنگام ساخت شیء اجرا می‌شود
        self.name = name         # ویژگی (attribute): داده‌ای که شیء نگه می‌دارد
    def speak(self):             # متد (method): کاری که شیء می‌تواند بکند
        return self.name + ": هاپ!"

اینجا self یعنی «خودِ همین شیء». حالا امتحان کنید: یک اسم بنویسید و از کلاس Dog شیء بسازید.

۵
متدهای ویژه (dunder): موتور پنهان پایتون


دلیل اصلی شیءگرا بودن مدل پایتون این است که هر عملگر و تابع داخلی، در واقع یک متد را روی شیء صدا می‌زند. نام این متدها با دو خط‌تیره شروع و تمام می‌شود (dunder = double underscore). با نوشتن آن‌ها، کلاس شما رفتار «بومی» پیدا می‌کند.


a + bصدا می‌زند: a.__add__(b)
len(x)صدا می‌زند: x.__len__()
x[0]صدا می‌زند: x.__getitem__(0)
print(x)صدا می‌زند: x.__str__()
for i in xصدا می‌زند: x.__iter__()
x()صدا می‌زند: x.__call__()


class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __add__(self, o):          # معنای عملگر +
        return Vector(self.x + o.x, self.y + o.y)
    def __str__(self):             # متنِ قابل‌نمایش شیء
        return f"({self.x}, {self.y})"

print(Vector(1, 2) + Vector(3, 4))   # (4, 6)






۶
پایتون و جاوا: تفاوت دقیق


جاوا را معمولاً الگوی «شیءگرایی سخت‌گیر» می‌دانند. مقایسه نشان می‌دهد پایتون کجا شیءگراتر و کجا منعطف‌تر است.


مدل دادهپایتون: همه‌چیز شیء است، حتی int. جاوا: نوع‌های ابتدایی مثل int شیء نیستند.
کپسوله‌سازیپایتون: قرارداد _x. جاوا: private واقعی.
وراثتپایتون: چندگانه با MRO. جاوا: تکی به‌علاوه interface.
نوع‌دهیپایتون: پویا با duck typing. جاوا: ایستا.
کلاس اجباری؟پایتون: خیر. جاوا: بله، هر کدی داخل کلاس است.


نتیجه دقیق: زبانی شیءگرا است که کلاس و شیء، کپسوله‌سازی، وراثت و چندریختی را پشتیبانی کند. پایتون هر چهار را دارد، و مدل دادهٔ آن حتی از جاوا یکدست‌تر است. تفاوتش در این است که بر پایه قرارداد و انعطاف کار می‌کند، نه اجبار. پس: شیءگرا و چندالگویی.

چرا به مترجم نیاز داریم؟


پردازنده فقط کد ماشین را می‌فهمد، یعنی دنباله‌ای از صفر و یک. زبان‌هایی مثل پایتون یا C برای انسان نوشته شده‌اند و به آن‌ها زبان سطح بالا می‌گوییم. پس یک واسط لازم است که کد منبع (source code) را به کد ماشین تبدیل کند. این واسط یا مفسر (Interpreter) است یا کامپایلر (Compiler).


تشبیه: مفسر مثل مترجم هم‌زمان در همایش است؛ جمله‌به‌جمله ترجمه می‌کند و همان لحظه به شما می‌رسد. کامپایلر مثل مترجم کتاب است؛ اول کل کتاب را ترجمه می‌کند و بعد شما فقط نسخه ترجمه‌شده را می‌خوانید.



۲
دو مترجم، دو روش


مفسر (Interpreter)
کد را هنگام اجرا می‌خواند، ترجمه و اجرا می‌کند. فایل اجرایی جدا تولید نمی‌شود و برای اجرا باید مفسر آن زبان روی سیستم نصب باشد. هر بار اجرا، ترجمه دوباره انجام می‌شود.
PythonJavaScriptRubyPHPPerlBashLua


کامپایلر (Compiler)
پیش از اجرا، کل کد منبع را بررسی و به کد ماشین (فایل اجرایی) تبدیل می‌کند. این فایل مستقیم روی پردازنده اجرا می‌شود و به runtime جدا نیاز ندارد. با هر تغییر در کد باید دوباره کامپایل کرد.
CC++GoRustSwiftPascalFortran

واقعیت دقیق: حالت ترکیبی


«مفسری» یا «کامپایلری» در عمل بیشتر ویژگی پیاده‌سازی است تا خود زبان. بسیاری از زبان‌ها ترکیبی‌اند: اول به بایت‌کد (bytecode) تبدیل می‌شوند و بعد یک ماشین مجازی آن را اجرا می‌کند. به همین دلیل پایتون هم مفسری و هم کامپایلری به شمار می‌آید.


C (کامپایلری خالص)
main.c→compiler→.exe→CPU

Java
Main.java→javac→.class→JVM

Python (CPython)
main.py→bytecode→PVM→CPU
